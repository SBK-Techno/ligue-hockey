## Release 1.12.0 (shipped)

- **Poll rail.** From 1280 px the discussion moves live polls into a sticky column: open polls first, then the newest closed ones, each keeping the shared close/delete menu from `ChatMessageActions.svelte`. Below 1280 px the polls stay inline. The server renders the inline layout and the mount resolves the real width before the first paint, so the client and server first render agree and the rail does not cause a hydration mismatch.
- **History on scroll.** The sentinel at the top of the stream loads the previous page through the authenticated `/api/discussion/messages?before=...` transport. Pages are merged by identity, and the first visible message plus its viewport offset anchor the reader while older messages arrive; the sentinel is observed only after the cache and the reading position have settled.
- **Reading position.** Each member's first visible message and offset are stored in a per-member localStorage key and restored after the cache is merged, paging older messages when the target is not in the first page. The restore holds across navigation and reload; the initial jump to the latest is instant and starts saving only afterwards.
- **Device conversation.** The full loaded conversation is mirrored per member in IndexedDB. A warm open hydrates the thread before the network, a 15 s delta sync brings new messages, deletions and poll states, and the cache computes its own oldest/latest cursors from the stored rows. One writer applies the message ceiling: an eviction removes the origin and stores `complete: false`, so a reload pages back with `before` instead of hiding the rest of the server history. A cached window that ends before the server page is bridged by `after`; an empty thread asks the latest page without a cursor, so the first message can arrive without a reload. Writes are refused once sign-out closes the member's cache, so an in-flight sync cannot repopulate it; a deletion overflow beyond the sync bound resets the device copy explicitly from the server. Sign-out clears the conversation and the reading position with a bounded wait, so a stalled store never blocks logout; the cleanup modules load only on that gesture, and the account menu does not pull the discussion cache into every page. The open burst is bounded by `config/chat.ts` and checked against `ABUSE_LIMITS.chatRead`; a sync refreshes the 100 most recent poll messages, and an older poll's state is refreshed by a full load.
- **Floating footer.** From 900 px the footer is fixed like the header: `tokens.css` owns `--footer-height`/`--footer-offset`, the shell reserves the height, the discussion composer and new-message pill sit above it, and print returns the footer to the flow. ## 1.6.0 shipped

- **Rink board.** `config/rink.ts` owns the geometry and presentation roles; `LineupBoard.svelte` renders both team halves, and the `?/lineup` action saves through `saveManualLineup` with the generation token. Pure placement rules live in `src/lib/ui/match/lineup-board.ts`; the board names every slot, keeps a stable key per place, and the manual save no longer publishes a lineup before teams exist.
- **Identity catalogue.** `config/legends.ts` holds 30 Canadiens tribute legends (15 forwards, 11 defense, 4 goalies) with name, number, position and era; `config/identities.ts` composes them with the 28 league faces into one catalogue of 58. The picker offers the legends of the selected position and keeps a saved legend from another position visible and flagged; the server enforces the same rule.
- **Identity uniqueness and active accounts.** `players_active_avatar_unique` is a partial unique index over active players; assignment, activation and profile writes reserve the identity in the same transaction. Reactivation revalidates a retired or taken identity. A deactivated account no longer acts with an old session, and a deactivated player is removed from future lineups.
- **Player peek.** Every avatar and player name opens one shared card from `getPlayerPeek`; season totals and position are public, ratings stay behind the ratings capability. The card is a hover popover on desktop and a sheet on mobile, and its cache policy follows the session policy.
- **Game-day correctness.** The match page reads the live roster and presence, the sheet appears only in a phase where it can accept events, a cancelled game cannot be scored, and the sheet and the ratings share one playability rule.
- **Security hardening.** Throttle buckets are bounded, member writes are rate-limited, lineup payloads are validated, and finance, settings and player writes are atomic with their audit entries. CSP is enabled, and response headers and cache policy have one owner.
- **Delivery budgets.** SSR HTML and JSON are compressed, critical CSS is inlined within its budget, the measured pages stay at the JavaScript request budget, and the client graph contains no zod. Content-hashed assets are served immutable for one year; a replaced name stays on disk for the retention window owned by `GENERATED_ASSET_RETENTION_DAYS`, so a document already in flight can finish loading it.
- **Operator signals.** `/api/health` and `/admin` share one queue snapshot (pending, failed, oldest due, suppression reasons, last-tick push counts); a `manageSettings` operator can retry a failed job with an audit entry, and the scheduler emits one `notification.queue_snapshot` per tick.
